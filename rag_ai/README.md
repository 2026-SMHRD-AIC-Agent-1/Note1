# AI 모의면접 - 재명 RAG / 언어 AI 파트

## 1. 목적
대기업·공기업 1차 서류 합격 후 실제 면접을 준비하는 지원자를 대상으로, 기업·직무·면접유형별 공개자료를 RAG로 검색해 질문과 평가포인트를 생성하고 답변 내용 분석·세션 코칭·반복연습 비교까지 제공한다.

현재 PoC
- 기업: SK하이닉스
- 직무: System Architecture / Software Solution
- 면접유형: A!SK 영상 인터뷰 / 심층 인터뷰
- 질문유형: 직무이해 / 문제해결 / 협업

## 2. 핵심 루프
면접 → 분석 → 약점 도출 → 다음 연습목표 → 재면접 → 이전 회차와 변화 비교

## 3. 재명 파트 기능
1. RAG 자료 Loading / Chunking / Embedding / FAISS 검색
2. A!SK 질문 3개 생성
3. 심층면접 첫 질문 1개 생성
4. 심층면접 답변을 바탕으로 꼬리질문을 최대 3개까지 순차 생성
5. 각 꼬리질문마다 평가포인트 3개 생성
6. STT 답변 내용 분석
7. 직무 핵심 반영도 / 답변 구성 충실도 계산
8. 세션 코칭
9. 1회차 ↔ 2회차 비교
10. 동일 입력 반복분석으로 점수 안정성 확인
11. MCP를 통한 외부 공식자료 보강(후속 적용)

## 4. 심층면접 꼬리질문 흐름
기본 흐름은 다음과 같다.

첫 질문 → 답변 → 꼬리질문 1 → 답변 → 꼬리질문 2 → 답변 → 꼬리질문 3 → 답변

- 꼬리질문은 최대 3개까지만 생성한다.
- 각 꼬리질문은 직전 답변에서 아직 충분히 설명되지 않은 한 가지를 더 깊게 확인한다.
- 이전 꼬리질문에서 이미 확인한 내용을 반복하지 않도록 `previous_followups` 기록을 함께 전달할 수 있다.
- 각 꼬리질문 결과에는 `question_text`, `question_reason`, `evaluation_points` 3개가 포함되므로 기존 `analyze_answer()`로 바로 평가할 수 있다.
- 하위 호환을 위해 `follow_up_question`, `follow_up_reason` 키도 함께 반환한다.

## 5. 역할 경계
- Frontend: 기업/직무/면접유형 선택, 질문 표시, 답변 녹화, 결과 표시
- Backend: Session/Question/Answer ID, 파일 저장, STT 실행, DB 저장, 각 AI 호출
- RAG/언어 AI(재명): 질문·평가포인트·답변분석·코칭·꼬리질문
- 비언어 AI(연진): 관찰 가능한 영상/음성 측정값과 전달 안정성 결과

## 6. GitHub 병합 원칙
- 각 파트 구현은 독립 폴더/브랜치에서 작업한다.
- 재명 파트는 내부 구현보다 입출력 JSON 규격을 먼저 고정한다.
- API 공통키: company, job, interview_type, question_type, evaluation_points, stt_text
- OpenAI API Key 등 비밀값은 코드에 저장하지 않고 환경변수로 관리한다.
- RAG 원문자료는 GitHub에 중복 저장하지 않고 별도 자료 폴더를 `RAG_BASE_PATH` 또는 `base_path`로 연결한다.
- main/develop 병합 전 샘플 Payload로 연동 테스트한다.

## 7. 점수 해석 주의
- 기업 내부 평가표나 합격 가능성을 추정하지 않는다.
- 점수는 연습용 지표다.
- 현재 점수체계는 `v8_answer_base95_excellence5`이다.
- 직무평가는 평가포인트 3개마다 공통 세부조건 5개를 True/False로 판단하고 Python이 100점으로 환산한다.
- 서로 다른 직무 평가포인트는 독립적으로 판단하며, 한 평가포인트의 좋은 설명을 다른 평가포인트 점수에 자동 재사용하지 않는다.
- 답변 구성은 4개 기준 × 4개 세부조건을 True/False로 판단한다.
- 답변 구성 기본평가는 최대 95점이고, 모든 답변에 별도 우수답변 조건 4개를 적용해 최대 +5점의 보너스를 더한다.
- 최종 답변 구성점수는 최대 100점이다.
- 상대지표는 초기에는 타인 백분위보다 본인 이전 회차 대비 변화를 우선한다.

## 8. MCP 적용 방향
현재 문제는 RAG 원본자료가 제한적이라는 점이다. MCP는 RAG를 대체하지 않고, 외부 검색 도구를 연결해 기업·직무·면접유형별 공식 공개자료를 찾아 검증 후 RAG에 보강하는 용도로 적용한다.
